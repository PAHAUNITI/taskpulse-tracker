## 1. Функциональные требования (Functional Requirements, FR)

| ID | Название требования | Описание действия системы | Роли пользователей |
| :--- | :--- | :--- | :--- |
| **FR-01** | Регистрация и управление профилем | Система обеспечивает создание учетной записи с валидацией email и безопасным хранением хэша пароля, а также редактирование профиля. | Администратор, Тимлид, Разработчик |
| **FR-02** | Аутентификация и RBAC | Система выполняет аутентификацию по логину/паролю с выдачей защищенных HttpOnly-сессий и разграничивает доступ к эндпоинтам согласно роли. | Все роли (Admin, Lead, Dev, Observer) |
| **FR-03** | Создание задачи в бэклоге | Система предоставляет форму создания тикета с атрибутами: заголовок, Markdown-описание, тип, приоритет, оценка в часах и автогенерация ключа `TP-XXX`. | Тимлид, Разработчик |
| **FR-04** | Редактирование и декомпозиция | Система позволяет изменять параметры задачи, декомпозировать ее на подзадачи (Subtasks) и прикреплять критерии приемки (Definition of Done). | Тимлид, Разработчик |
| **FR-05** | Интерактивная смена статусов | Система обеспечивает перемещение карточек на Kanban-доске между колонками (`Backlog` → `To Do` → `In Progress` → `Code Review` → `Done`) через Drag-and-Drop. | Тимлид, Разработчик |
| **FR-06** | Назначение исполнителя | Система позволяет закрепить задачу за конкретным разработчиком (Assignee) с проверкой его текущей занятости и лимита доступных часов. | Тимлид |
| **FR-07** | Учет трудозатрат (Time Tracking) | Система фиксирует списание фактически затраченного времени (Worklog) с комментарием и автоматически пересчитывает поля `time_spent` и `time_remaining`. | Разработчик, Тимлид |
| **FR-08** | Управление спринтами | Система позволяет формировать пул задач спринта, задавать даты и цели (Sprint Goal), запускать и завершать итерацию с фиксацией скоупа. | Тимлид |
| **FR-09** | Git Webhook интеграция | Система принимает HTTP POST вебхуки Git-серверов (GitHub/GitLab), парсит ключ тикета из коммита и автоматически связывает хэш коммита и ветку с задачей. | Внешний Git-сервер, Все роли |
| **FR-10** | Фильтрация и поиск | Система обеспечивает многокритериальную фильтрацию доски (по исполнителю, спринту, приоритету, статусу) и полнотекстовый поиск по названию тикета. | Все роли |
| **FR-11** | Аналитика спринта и Burndown | Система строит двухосевой график сгорания задач (Sprint Burndown Chart) и сводный табель трудозатрат (Timesheet) команды за выбранный период. | Все роли, Наблюдатель |
| **FR-12** | Контроль WIP-лимитов | Система осуществляет проверку максимального числа задач в колонках `In Progress` и `Code Review` и визуально блокирует перегрузку с предупреждением. | Тимлид, Разработчик |

## 2. Нефункциональные требования (Non-Functional Requirements, NFR)

| ID | Категория качества | Измеримое требование |
| :--- | :--- | :--- |
| **NFR-01** | **Производительность** | Время отклика REST API на базовые CRUD-операции не превышает 200 мс при 95-м перцентиле (p95); полная отрисовка Kanban-доски (до 100 карточек) не превышает 500 мс. |
| **NFR-02** | **Безопасность** | Пароли пользователей хэшируются с использованием алгоритма Argon2id или bcrypt (cost $\ge 12$). Сессионные токены передаются строго через HttpOnly, Secure, SameSite=Lax Cookie. |
| **NFR-03** | **Надежность** | Система гарантирует сохранность данных при внезапном сбое питания за счет транзакций СУБД (ACID) и автоматического перезапуска контейнеров (Docker policy: `unless-stopped`). |
| **NFR-04** | **Usability (Удобство)** | Интерфейс строится по дизайн-системе Linear UI (сетка 8pt, темная/светлая тема), перемещение задач реализуется в 1 действие Drag-and-Drop с Optimistic UI без перезагрузки экрана. |
| **NFR-05** | **Совместимость** | Веб-интерфейс функционирует без искажений во всех браузерах на базе Chromium (Chrome, Edge 110+), Firefox 115+ и Safari 16+ на разрешениях от 1280×720 до 4K. |
| **NFR-06** | **Масштабируемость** | Архитектура поддерживает одновременную работу до 50 активных участников команды и ведение до 10 000 задач на проект без деградации времени ответа более чем на 15%. |
| **NFR-07** | **Сопровождаемость** | Исходный код разбит на слабосвязанные модули (<800 строк/файл), функции содержат до 50 строк; покрытие доменной логики unit-тестами составляет не менее 80% (факт: 99%). |
| **NFR-08** | **Ограничения среды** | Потребление оперативной памяти микросервисами системы не должно превышать 512 МБ RAM; развертывание выполняется одной командой `docker compose up -d` без внешних SaaS-зависимостей. |
| **NFR-09** | **Отказоустойчивость** | Предусмотрено создание ежедневных резервных копий (бэкапов) базы данных с возможностью полного восстановления состояния проекта не более чем за 5 минут. |
| **NFR-10** | **Аудируемость** | Все критические операции (смена статуса, удаление задач, изменение ролей) фиксируются в журнале аудита с неизменяемой отметкой времени ISO 8601 и идентификатором пользователя. |
